# Board art

Every board graphic is a JPG in `public/board/`. Replace a file with your own image **with the same
name and size** and it appears in the game. Delete a file and that piece falls back to the
built-in CSS look, so you can work one image at a time.

## Workflow

1. `npm run dev`, then open **http://localhost:3000/art-preview**: the board with a sample game
   in progress, plus a ✓/✗ checklist of every file. No sign-in needed.
2. Open a template from `public/board/` in your image editor, paint over it, and save it as JPG
   with the same name (quality ~85, ideally under 300 KB each).
3. Hard-refresh the preview (Ctrl+Shift+R).

### From one full-board picture

If you have the whole board as one image (7×7 layout, Start bottom-right, squares in the game's
order), cut it up automatically:

```bash
npm run art:slice -- art/source/board.jpg            # writes 24 squares, centre, background
npm run art:slice -- art/source/board.jpg --dry-run  # only show the detected grid
```

It finds the squares from the dark gaps between them, so the picture doesn't need a perfectly
regular grid. Non-square cells are padded with their own edge colour (text isn't stretched),
and the centre is cropped square from the middle. **It overwrites** those 26 files. Tokens, dice
and the Fortune card are separate files that it doesn't touch. Higher-resolution sources give
sharper squares (each square should ideally be at least 300 px in the source).

### Player tokens from a 2×2 character sheet

```bash
npm run art:tokens -- art/source/tokens.png
npm run art:tokens -- "sheet.png" --order 4,1,2,3
```

Crops each figure to head and shoulders (tokens are small circles) and writes
`tokens/token-1..4.jpg`. `--order` says which sheet position (1 top-left, 2 top-right, 3
bottom-left, 4 bottom-right) becomes player 1..4; match the player colours (1 yellow, 2 red,
3 blue, 4 green). With token art present, tokens are drawn larger so the characters are
recognisable.

### Templates

The starter templates are generated by `npm run art:templates` (Python + Pillow). It only creates
**missing** files and never overwrites your art; `npm run art:templates -- --force` regenerates all
of them (this deletes your art).

## Files and sizes

| File | Size (px) | Notes |
| --- | --- | --- |
| `background.jpg` | 2100×2100 | Behind the whole board; only the thin gaps and edge show. |
| `center.jpg` | 1500×1500 | Inside the ring of squares. With this file present, the game shows round, dice, Jackpot and the Fortune card on a dark panel over the **bottom third** (about the middle 64% of the width), and hides the built-in "RENT RUSH" title: put your title in the upper part. Don't paint dice or a Jackpot amount; the game shows the real ones. |
| `squares/00-start.jpg` … `squares/23-golden-mile.jpg` | 300×300 each | One per square, numbered clockwise from Start. Your art carries the name and price (the built-in text is hidden when the image exists). |
| `tokens/token-1.jpg` … `token-4.jpg` | 128×128 | Player pieces, shown cropped to a circle with a player-colour ring. |
| `dice/die-1.jpg` … `die-6.jpg` | 160×160 | Die faces, shown with rounded corners. |
| `cards/fortune.jpg` | 600×340 | Background of the Fortune card; the card text is drawn on top. |

The full list (with the square names) lives in `game/art.ts` and on the preview page.

## Overlays drawn by the game

The dashed boxes in the templates show where the game draws live information on top of your art:

- **Squares:** owner dot plus ▲ upgrade pips in the **top-right** corner; player tokens along
  the **bottom-left** edge; a coloured border in the owner's colour; a gold outline on the
  current player's square.
- **Centre:** round counter, dice, Jackpot and Fortune card, on a panel at the bottom when
  `center.jpg` exists (stacked in the middle without it).

Squares appear about 60–110 px wide on screen, so bold shapes and large text read best.
